# app_settings keys

Ключи в таблице `app_settings`, которые использует приложение.

## Глобальные настройки

- `check_interval_minutes` — интервал авто-проверок в минутах (`0` = отключено).
- `last_checks_run_at` — отметка времени последнего фактического запуска `check.php`.
- `alert_email_recipients` — список email через запятую для уведомлений.
- `alert_telegram_recipients` — список Telegram `chat_id`/`@username` через запятую для уведомлений.

## Состояние уведомлений по сайту

Для сайта с id `N`:

- `site_state_N` — текущий подтвержденный статус (`unknown` / `up` / `down`).
- `site_fail_count_N` — количество подряд неуспешных проверок.
- `site_success_count_N` — количество подряд успешных проверок.
- `site_recheck_pending_N` — флаг ожидаемой быстрой перепроверки (`1`/`0`).
- `site_recheck_due_N` — время (UTC), когда нужно выполнить быструю перепроверку.

### Быстрая перепроверка после первой ошибки

Текущая логика алертов:

- первая неуспешная проверка ставит быструю перепроверку через 2 минуты;
- если перепроверка тоже неуспешна, состояние подтверждается как `down` и уходит DOWN-алерт;
- при успешной проверке флаг быстрой перепроверки сбрасывается.

## Логика мульти-ссылочного мониторинга

- У каждого сайта может быть несколько URL для проверки (каждый URL — отдельный endpoint).
- Режим доступности задаётся в `config.php` / `.env` (`CHECK_AVAILABILITY_MODE`):
  - `primary` (по умолчанию) — up/down определяет только первая ссылка;
  - `all` — сайт down, если упал хотя бы один endpoint;
  - `any` — сайт up, если доступен хотя бы один endpoint;
  - `majority` — сайт up, если доступна большая часть endpoint-ов.
- Проверка endpoint-а выполняется как HEAD, при ошибке/неуспехе — повтор GET с browser-like заголовками (`CHECK_RETRY_WITH_GET=true`).
- В таблицу `checks` сохраняется агрегированный результат по сайту за запуск.
- В таблицу `endpoint_checks` сохраняются детальные результаты по каждому endpoint.
- В DOWN-уведомлениях перечисляются проблемные ссылки, которые подтвердили инцидент.

## Троттлинг старого DOWN-алерта

Старый ключ, может встречаться в БД от прежней логики:

- `last_down_email_site_N` — последнее время отправки DOWN-уведомления.

Примечание: новая логика алертов использует состояние и пороги антифлапа, поэтому этот ключ можно считать legacy.
